# 现代汉语语法与标点校稿技能

## 触发条件

用户要求对博客日志、说说或其他文档进行语法校验、标点检查、校稿时触发。可通过 `/proofread` 手动调用，也可传参指定范围，如 `/proofread 最近3篇`。

## 参数说明

- `$ARGUMENTS`：可选。指定校验范围，例如：
  - 留空或 `all`：校验所有日志和说说
  - `最新` 或 `最近N篇`：只校验最近的N篇文章
  - `blogId=xxx`：只校验指定ID的文章
  - `说说`：只校验说说
  - `标题关键词`：按标题匹配校验

## 校验规范（严格遵循）

### 一、标点符号规范（GB/T 15834-2011）

1. **句号（。）**：陈述句末尾使用句号，不使用英文句点(.)
2. **逗号（，）**：句子内部停顿使用中文逗号，不使用英文逗号(,)
3. **顿号（、）**：并列词语之间使用顿号，最后两项用"和/与/及"连接时前面不加顿号
4. **分号（；）**：并列复句各分句之间使用分号
5. **冒号（：）**：提示性话语后使用冒号，不使用英文冒号(:)
6. **引号（""''）**：使用中文引号，不使用英文引号；引用内容嵌套时外双内单
7. **破折号（——）**：占两个汉字位置，使用全角破折号
8. **省略号（……）**：六个点，占两个汉字位置
9. **问号（？）**：疑问句末尾使用问号
10. **感叹号（！）**：感叹句末尾使用感叹号
11. **书名号（《》）**：书名、文章名、篇名使用书名号
12. **括号（）**：使用中文全角括号
13. **连接号**：相关字母数字间用半角连接号"-"，汉字间用一字线"—"或波浪号"～"

### 二、语法规范

1. **主谓宾完整**：检查并修正残缺的主语、谓语或宾语
2. **搭配得当**：动宾搭配、修饰语与中心语搭配是否合理
3. **语序正确**：定语、状语、补语位置是否符合汉语习惯
4. **关联词搭配**："虽然…但是…"、"因为…所以…"等关联词必须成对使用
5. **时态助词**："的、地、得"使用正确：定语后用"的"，状语后用"地"，补语前用"得"
6. **量词正确**：名量搭配是否符合现代汉语习惯
7. **代词指代明确**：避免代词指代不明
8. **避免语病**：
   - 成分残缺或赘余
   - 句式杂糅
   - 中途易辙（主语中途更换未交代）
   - 前后矛盾
   - 否定失当（多重否定导致表意相反）
9. **"的"字用法**：避免"的"字滥用，该省则省
10. **冗余表达**：删除不影响句意的重复词语
11. **表述统一**：同一语境中出现的同类数值（身高、距离、时间等）应使用统一的表述格式。如口语化文章中身高统一用"1米7""1米85"，而非混用"1.7""1米93"等不同格式。需根据上下文语境判断应采用口语化还是书面化表述
12. **错别字/形近字**：检查并修正形近字、音近字导致的错别字，如"原故→缘故""帐蓬→帐篷""拔涉→跋涉"等。对于不属于常见易错字、但读起来明显不通顺的词语，应结合上下文判断是否为错别字

### 三、标点易错点专项（重点检查）

1. **多余逗号**：一个完整句意内部不应出现过多逗号堆砌，该用句号断句的地方不要用逗号连缀（即"一逗到底"问题）
2. **多余句号**：句末不应出现连续句号（如"。。"），段落内部不应有多余的句号截断语意
3. **误用分号当句号**：独立完整的句子之间应使用句号，非并列关系不应使用分号连接
4. **误用句号当分号**：并列复句各分句之间应用分号，不应使用句号割裂
5. **顿号错用为逗号**：并列词语之间应用顿号（、），而非逗号（，），如"苹果、香蕉、橘子"而非"苹果，香蕉，橘子"。**特别注意并列定语**：共同修饰一个名词的多个定语之间应用顿号，如"属于我的、花园里的朝花"而非"属于我的，花园里的朝花"
6. **逗号错用为顿号**：并列的分句或短语较长时应用逗号，不用顿号。**顿号与逗号的选择标准**：不以字数为硬界限，而看并列项的**结构复杂度**——如果并列项内部包含"的"字结构或更复杂的修饰语（即每个并列项自身有修饰层次），用逗号；如果并列项是简单词/短语，用顿号。拿不准时保持原文不动
7. **冒号错用为分号**：提示性话语后面应使用冒号引出内容，不使用分号
8. **引号内外标点**：引文完整且独立使用时，句号放在引号内；引文作为句子一部分时，句号放在引号外
9. **文学性顿号与逗号**：在散文、随笔等文学性写作中，顿号和逗号常用于标示**语气停顿、节奏和情绪**，而非仅标记语法关系。如"莫名的、暖暖的"、"远远的、亮亮的灯火"，中间顿号制造呼吸感；又如"很安静，很温暖，很踏实"，逗号拉开节奏让情绪一层层铺开。这些属于修辞用法，**不得机械地删除或合并**。判断标准：如果去除该标点后读起来节奏感明显变差、情绪表达被削弱，则保留原文
10. **区分文学性逗号与逗号滥用**：这是两个截然不同的概念，校稿时必须仔细甄别：
    - **文学性逗号（保留）**：作者有意用逗号控制节奏、营造氛围、层层递进。特征：每个逗号前后语意相对独立，去掉逗号后节奏明显变急促，丢失了作者想要的那种"慢下来"的效果。例如："他站在那里，一动不动，像一棵树。"
    - **逗号滥用（需修正）**：作者无意识地将多个完整句子用逗号串联，形成"一逗到底"。特征：逗号连接的几个部分各自主谓完整、语意独立，完全应该各自成句，用逗号连接反而让句子臃肿、层次不清。例如："他走进了教室，老师正在讲课，同学们都抬起头看他，他有些不好意思地低下了头。"——这里每个分句主谓完整，应断为独立句子
    - **判断口诀**：读一遍，如果逗号处是"该喘口气"（有意节奏）就保留，如果是"该画句号却没画"（无意识堆砌）就修正
11. **标题结尾标点**：章节标题、文章标题末尾一般不加句号。但需**智能判断标点的语气功能**：
    - 问号（？）如果承载了语气功能——表达不确定、推测、反问、疑惑等语气——应保留。例如："运气不佳，似乎有些失望？"中问号传达"似乎"的不确定推测语气，去掉后语气变为肯定陈述，改变了原意，不应去掉
    - 感叹号（！）如果承载了强调、惊讶等情感语气，应保留
    - 省略号（……）如果表达未尽之意、余韵，应保留
    - 句号（。）在标题结尾通常是多余的，应去掉
    - **判断原则**：去掉标点后默读一遍，如果语气、情感或语义发生了变化，说明该标点不可去掉

### 四、专有名词与特殊用法白名单（不判定为误用）

以下类型不做修改，保持原文：

1. **饮食类专有名词**：手把肉、青稞酒、片儿川、泡面、汤达人、红烧牛肉泡面等地方特色食品名称
2. **地名专有名词**：乌拉盖、乌兰浩特、阿尔山、乞颜部落、察哈尔、野狼谷等
3. **网络用语/口语化表达**：如原文中使用引号标注的网络用语、口语表达，保持原样
4. **引号内具有特殊含义的词**：如"永动机"、"情绪价值"、"氛围感男神"等加引号表示特殊含义或调侃的词语，不做修改
5. **方言表达**：保留作者使用的方言词汇和地方表达习惯
6. **作者自创或特殊修辞用法**：如"片儿川"用于指代其他面食（有上下文语境的幽默用法）等
7. **品牌名/外文缩写**：如FM91.8、AK、T3等
8. **表情符号及颜文字**：如(*^▽^*)、（￣～￣;）、(¬_¬)ﾉ等保持原样不修改

### 五、绝对禁止事项

1. **严禁篡改内容**：不改变作者的原意、观点、情感和叙事内容
2. **严禁删减段落**：不删除任何段落或句子
3. **严禁添加内容**：不添加作者原文中没有的词语或句子
4. **严禁改变风格**：保持作者原有的语言风格和表达习惯
5. **严禁统一改写**：不能将所有文章改写成同一种风格

## 执行流程

### 步骤1：读取数据

```bash
# 读取博客数据
py -c "
import json, base64, sys
sys.stdout.reconfigure(encoding='utf-8')
with open('Blogs/json/blogs.js', 'r', encoding='utf-8') as f:
    content = f.read()
data = json.loads(content[len('window.blogs = '):])
# 根据 $ARGUMENTS 筛选目标文章
# 输出文章的 blogId 和标题列表
"
```

### 步骤2：逐篇校验

对每篇文章执行以下操作：

1. Base64 解码 `custom_html` 字段，提取纯文本
2. 逐句检查标点符号规范性
3. 逐句检查语法规范性
4. 记录所有需要修改的位置，生成修改对照表

### 步骤3：展示修改方案

向用户展示修改对照表，格式如下：

```
文章：《xxx》
━━━━━━━━━━━━━━━━━━━━
第X段：
  原文：...错误的内容...
  修改：...正确的内容...
  说明：[修改原因]
━━━━━━━━━━━━━━━━━━━━
```

### 步骤3.5：不确定项的处理

对于拿不准的修改（如顿号/逗号选择、语气判断、表述统一等灰色地带），遵循以下原则：
1. 以AI自身的判断为主，先按自己的理解给出修改建议
2. 必须将原文和修改后的内容完整展示给用户对照
3. 在说明中标注"（待确认）"，让用户自行判断是否接受
4. 用户确认后才执行修改

### 步骤4：等待确认

展示完所有修改后，询问用户是否确认修改。用户确认后才执行。

### 步骤5：执行修改

用户确认后：
1. 在 HTML 中执行替换
2. Base64 重新编码
3. 写回 `blogs.js`
4. 如果修改了摘要（abstract），同步更新
5. **标记校对文章**：为所有本次校对过的文章添加 `"custom_proofread": true` 字段，以便重新采集时通过 `merge.py` 保留校对修正。标记代码示例：

```python
for b in data:
    if 本次校对过此文章:
        b['custom_proofread'] = True
```

### 步骤6：提交

```bash
git add Blogs/json/blogs.js
git commit -m "Proofread: fix grammar and punctuation in [文章标题]"
```

## 注意事项

- 每次只校验和修改用户指定的文章范围
- 修改前必须先展示方案并获得用户确认
- 如果一篇文章没有需要修改的地方，直接告知用户"该文章语法和标点均符合规范"
- 修改时保持 HTML 标签结构不变，只修改标签内的文本内容
- Python 环境使用 `py` 命令，脚本头部加 `# -*- coding: utf-8 -*-`
